# M3a 企业登录与账号安全

平台管理员可在实例设置登记一个 OIDC 身份服务：显示名称、Issuer、Client ID、可选 Client Secret、scopes、登录开关及首次建号开关。默认关闭，首次建号独立默认关闭。密钥加密保存，接口只显示已配置状态；留空保留，清除需显式操作。

登录页保留账号/密码，开启后增加企业登录按钮。用户完成企业验证，已绑定身份进入原本地账号；未绑定且允许 JIT 时，以已验证的新邮箱创建无管理权限普通账号。与本地已有邮箱相同、邮箱未验证或 JIT 关闭时，提示先本地登录后绑定或联系管理员。企业角色声明不参与授权。

头像菜单内的「账号资料」页仅平台登录用户可见，展示绑定状态、身份来源及本地密码可用性。绑定需确认本地密码，随后重新验证企业身份；解绑也需本地密码，SSO-only 用户需先通过管理员开放的邮件恢复流程设置本地密码。绑定更改后撤销旧会话和账号挑战；当前浏览器获得新会话。每用户绑定一个身份。

权限：读取及更改自己的关联只需有效 session，写入另需 CSRF/本地密码；更改企业设置与连接检查需 settings:write 且真实超管。至少保留一个 active 本地密码超管。非平台接口返回 404，不创建身份表，也不引入登录页面。

验收范围：真实签名 IdP 的授权码与 PKCE、浏览器绑定、state/nonce/重放拒绝，JIT 最低权限、邮箱冲突、显式绑定/解除、配置变更/账号禁用撤销、密码回退；SQLite/PostgreSQL/MySQL 的同组事务与迁移；PC/375px、浅/深/system、键盘、loading/error/success；真实 Wails 冒烟与主题替换回归。

限制：已验证隔离 IdP，尚未连接客户真实企业租户；只支持一个 Issuer，不做企业权限同步、SCIM 或单点退出。品牌上传和自动升级仍属后续增量。

当前身份以 [ADR-0037](../adr/ADR-0037-unified-user-identity.md) 为准：两个工作台共用统一账号、角色、绑定与会话，不存在独立管理员账号/会话表。/api/v1/auth/oidc/callback 与 /api/v1/admin/auth/oidc/callback 保留固定工作台入口，各自验证浏览器流程证明；管理入口禁止 JIT，不能通过切换入口绕过账号绑定及权限校验。后台配置与连接检查在同一企业登录标签；本人改密验证旧密码并撤销该账号旧会话/挑战。ADR-0014 仅保留历史背景。

未设置本地密码的已绑定账号可在安全设置重新验证企业身份后设置本地 TOTP，不依赖邮件或本地密码。企业验证必须匹配原绑定 issuer/sub、原账号与当前会话，不能自动创建或绑定其他身份；验证码确认前仍受强制 2FA 限制。已有本地密码继续使用密码确认。企业认证与本地 TOTP 为独立两层验证，不消费企业 amr/acr 跳过本地校验。

IdP 兼容层：id_token 缺少 email 时可开启 userinfo 补全（仅补空字段，不覆盖已验证值；点路径可适配非标准载荷）；`email_verified` 缺失的 IdP 可关闭"企业邮箱必须已验证"允许 JIT；发现文档残缺的 IdP 可逐项手动覆盖授权/令牌/userinfo/JWKS 端点（覆盖发现结果，无发现文档时四项齐备即可接入）。连接检查展示实际生效端点。邮箱与本地账号冲突时不再死路：回调改为发放一次性 5 分钟绑定邀请（独立浏览器证明 cookie），登录页展示"绑定企业账号并登录"卡片，密码证明（TOTP 账号随后走既有 MFA 步骤）通过后单事务完成链接、旧会话吊销与登录；失败即消耗邀请，需重新发起企业验证。仅用户域提供绑定登录，管理员域保持先本地登录再绑定。
