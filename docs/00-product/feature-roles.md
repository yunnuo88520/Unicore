# 平台用户与固定角色

仅 web-platform 装配身份与权限。每个用户只关联一种角色：管理员（兼容 ID super_admin）或普通用户（user）。角色与管理权限由代码固定，不提供自定义角色、委派或角色写接口。角色页为只读目录，显示两种角色、用户数量和权限矩阵。

| 能力 | 管理员 | 普通用户 |
| --- | --- | --- |
| 工作空间、共享 Core、本人账号安全 | 允许 | 允许 |
| 当前客户端浅色/深色/跟随系统 | 允许 | 允许 |
| 平台仪表盘、审计概览 | 允许 | 拒绝 |
| 用户搜索/分页/创建/两角色分配/启停 | 允许 | 拒绝 |
| 角色权限目录 | 允许 | 拒绝 |
| 全局站点/品牌/安全/SMTP/账号/OIDC/授权升级设置 | 允许 | 拒绝 |

全局设置影响所有用户，但只有管理员能进入配置界面及读写管理 API。公共 bootstrap、Logo/favicon、站点名、版权和登录策略仅返回页面运行所需的公开投影，不公开 SMTP、企业密钥或管理数据。普通用户设置入口只显示本地外观，不挂载全局设置组件、不请求管理接口、不写服务器。

前端统一 routes.ts 与 isAdministrator 控制菜单和直达页面；服务端对每个管理 API 校验当前 session、固定管理员角色和权限，写入再校验 CSRF/Origin。普通用户即使带有历史 role_permissions 管理 grant 也不能授权。创建和身份变更在安装行锁事务内复核操作者，不能禁用或降权最后一个启用管理员，以及最后一个具备本地密码的启用管理员。

注册和 OIDC 首次建号固定为普通用户，不从外部 claim 导入管理员。管理员改变角色或状态会撤销全部旧会话与待用账号挑战，重新登录后才获得新身份。

0007 升级保留管理员、账号密码和其他设置；旧自定义角色账号降为普通用户，删除自定义角色与非管理员 grant，清除平台全局 appearance.theme。全部旧会话、账号令牌、数字码和 OIDC 流程失效，待发邮件取消，用户重新登录/申请。升级前停服成套备份，恢复须匹配 DB/配置/密钥和程序版本，见 [部署手册](../03-runbooks/deployment.md)。

验收包含逐个管理 API 的匿名 401/普通用户 403、CSRF、历史 grant 越权、最后管理员保护、升降级会话撤销、两客户端外观隔离、公共品牌和三数据库旧数据升级。见 [ADR-0012](../adr/ADR-0012-fixed-platform-roles.md) 与 [验收](../04-ai/acceptance-permissions.md)。原 M2d 业务角色方案已被本规范取代。
