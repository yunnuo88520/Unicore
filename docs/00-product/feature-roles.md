# 平台用户与角色权限

仅 web-platform 装配账号体系。全部账号存于 unicore_users，一个用户通过 unicore_user_roles 持有一到多个角色，业务成员、部门负责人、运营和系统管理是同一个账号的不同授权。用户和管理工作台保留独立页面与 API 入口，共用账号、Cookie、会话、个人资料、改密、找回、TOTP 与企业绑定；账号名、邮箱及手机号全局唯一。详见 [统一账号决策](../adr/ADR-0037-unified-user-identity.md)。

账号创建与编辑支持 role_ids 多角色集合；角色权限及 menu_ids/action_ids/operation_ids 分别取并集，菜单只影响入口，不授权 API。每个请求由后端按权限点、适用的 operation grant、超级管理员保留策略与 CSRF/Origin 校验。角色可同时持有业务和管理权限；realm 仅保留为工作台分类元数据。角色授权编辑器使用单棵共享树，节点 ID 全局唯一且无工作台前缀，surfaces 声明适用工作台。勾选子页面自动补齐祖先链，只联动角色权限上界内的 GET 浏览接口；共享页面默认使用用户工作区接口，管理变体可显式授权。按钮展开在页面下，勾选按钮补齐其权限点及 API，取消按钮只撤销动作行；取消菜单保留独立动作/API。高级区提供完整可委派 API 选择器（包括未关联页面的接口）和权限点；无需菜单即可配置纯 API 角色。all 模式操作补齐全部必要点，any 模式先选择一个分支，不补兄弟权限。保留点使用服务端 PermissionDefinition.super_admin 元数据展示为不可委派。角色列表展示数据范围并支持复制角色。

超级管理员可直接为已有账号分配和撤销角色。仅有用户创建/编辑权限的运营人员可以创建默认成员、编辑状态和组织归属，不能借此变更角色或修改超管账号。公开注册与企业 JIT 固定 user，不接收客户端角色声明。super_admin 可以与其他角色并存，拥有全部权限；最后启用超管及最后有本地密码超管受事务保护。系统设置写入、角色管理、更新安装与存储配置等保留操作仍需超管。

部门树、岗位和数据范围适用于统一账号。岗位不隐式授权；角色数据范围支持仅本人、本部门、本部门及以下、自定义部门、全部账号，仅持有当前资源权限点的角色参与范围并集。用户列表/导出以及创建、修改均受对应范围约束；目标部门变更也需范围校验。全部范围可能包含持管理角色用户的数据，业务必须显式选择适用范围。

个人资源归属固定使用 user 身份，切换工作台不创建第二份文件、头像或笔记。管理文件操作仍需对应管理权限。个人中心与安全流程见 [个人中心](../03-runbooks/personal-center.md)。账号停用、改密及角色权限变化撤销共享会话，安全策略根据实际权限生效。

该未发布重构仅支持新安装，不提供旧双身份数据库迁移。新安装三方言均不创建独立管理员账号及其配套表。web-standalone、desktop 和 cli 的装配边界不变。

内置 user 是公开注册与企业 JIT 的默认角色，只允许业务权限与本人数据范围；管理权限通过额外自定义角色授予，不能把默认注册角色改成管理角色。编辑器将其数据范围固定为 self 并只读，复制为自定义角色后可调整范围；super_admin 的保留策略不变。

管理端凭据使用独立 users:credentials:write，可委派给自定义角色处理范围内的普通业务目标，不自动授予旧角色。密码重置校验该新权限及目标范围；实际修改登录邮箱同时校验 users:update 的目标/目的部门范围和新权限的目标范围。邮箱 trim、小写化后未变不触发新增凭据鉴权。完整目标账号按 HasManagementAccess 判断管理能力，这类账号的密码/登录邮箱仅超管可改，不能只保护 super_admin 角色名；目标不受操作者 PAT 单角色投影裁剪。所有管理端凭据写均禁止 PAT，含本人和超管绑定令牌。本人 account 安全流程继续独立验证，详见 [ADR-0046](../adr/ADR-0046-credential-delegation-role-concurrency.md)。

角色更新必须提交读取到的正整数 version，缺失/非法拒绝、过期 409，成功 CAS 递增；创建无需 version。省略授权与范围字段仍保留原值。角色编辑冲突后由用户显式重读并复核，不能自动用新 version 重试。菜单节点补丁、兼容整树分配、导航裁剪/启动物化和部门范围清理等聚合写入口实际改变角色时也维护版本，用户成员数变化不使角色编辑过期。platform@4 为三方言追加角色版本列，已有及新建角色从 1 起；三个 UI profile 同步迁移不代表 Standalone 开放身份治理，见 ADR-0046。

菜单直达、按钮与 API 的独立授权、角色更新保留语义见 [ADR-0038](../adr/ADR-0038-rbac-enforcement.md)。

菜单行展示已分配角色，并提供超管专用“分配角色”弹窗。提交 `PUT /admin/menus/{id}/roles`，携带导航 version、当前观察到的 expected_role_ids 与目标 role_ids；事务合并当前角色记录，只改当前菜单及新增所需祖先/浏览授权，保留其他权限、按钮、API、名称与范围。导航版本或当前成员集合改变返回 409，关闭弹窗重新读取后再分配；实际改动角色授权时同时递增该角色 version。仅受影响角色成员的共享会话失效。目录分配仅处理当前目录，不批量授予子页面。菜单行只显示显式分配角色，不声称最终可达；最终可见仍受 surface、区域/节点及祖先隐藏禁用约束，super_admin 的默认访问也不绕过这些约束。分配弹窗固定勾选且禁用 super_admin 行，不将其写入可编辑 role_ids/expected_role_ids；未分配、加载中与加载错误分别呈现，不能把加载失败当空集合。

显式空 action_ids 是撤销意图，会话解析与启动回填均不得恢复；只有尚未初始化的旧角色可在启动初始化边界物化一次。已初始化角色缺失的按钮必须重新显式勾选。独立“API 操作目录”页面与菜单已移除，后台目录接口继续为高级 API 授权供数。当前交互与兼容规则见 [ADR-0040](../adr/ADR-0040-explicit-role-grants.md)。
