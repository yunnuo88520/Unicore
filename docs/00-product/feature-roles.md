# 平台用户与角色权限

仅 web-platform 装配身份。管理员（super_admin）和普通用户（user）分别使用独立账号、会话、验证码、恢复和企业绑定表；相同用户名/邮箱可以并存，凭据不能跨域使用。**双域角色可运营**：管理员域在固定 super_admin 之外可创建受限管理员角色并分配给管理员账号（roles:write、管理员管理、系统设置、更新安装、存储写入仍仅 super_admin，[ADR-0034](../adr/ADR-0034-administrator-restricted-roles.md)）；用户域角色按 assignable 权限点组合业务权限，写操作按钮由独立动作权限点逐点控制（[ADR-0035](../adr/ADR-0035-action-permissions-departments.md)）。在权限点之上，角色分别授予三类能力：`menu_ids`（菜单/页面入口）、`action_ids`（页面动作）与 `operation_ids`（可委派 API），三类授权独立勾选、互不隐含，空数组提交被拒绝（[ADR-0036](../adr/ADR-0036-navigation-regions-granular-authorization.md)）。角色页按用户/管理员两个域管理，受限管理员对角色页只读。管理员与用户侧栏由真实导航区域组成（按 `surface=user|administrator` 隔离的区域与目录/页面/链接/动作节点树），默认区域、成员与顺序由代码显式定义，操作员可通过菜单管理（区域树编辑，支持目录嵌套与外部链接）调整并持久化，见 [管理工具](../03-runbooks/admin-tools.md)。

| 能力 | 管理员 | 普通用户 |
| --- | --- | --- |
| 工作台概览、Core、本人个人中心/改密/企业绑定 | 允许 | 允许 |
| 当前客户端外观 | 允许 | 允许 |
| 独立用户/管理员列表、弹窗新增、启停 | 允许 | 拒绝 |
| 角色权限目录 | 允许 | 拒绝 |
| 基础设置、邮件设置、系统日志、系统更新/授权占位 | 允许 | 拒绝 |

管理员从可配置后台入口（默认 /admin）登录，普通用户从 /login 或 / 登录。公开登录壳不提供管理数据；两域使用不同 Cookie 与固定 API 路径；管理员路径统一 /api/v1/admin/*，不能自动回退。安装后的初始账号写入管理员表，完成页跳转后台。注册和企业 JIT 仅建普通用户，管理员 JIT 禁止；绑定按 issuer/sub 识别，不按邮箱合并。

工作台概览一级默认。用户管理包含用户列表、管理员列表、角色权限、部门管理、岗位管理；“系统管理”分区下的系统设置组承载全局设置类页面，个人中心包含个人资料、安全设置和登录会话。普通用户只显示被授予菜单的个人域页面与当前客户端外观。侧栏、图标栏与移动抽屉消费同一导航模型：选中背景仅在实际二级页面，父级仅用文字色提示；直达页面自动展开所属路径，被授权过滤的父级整树隐藏。固定侧栏导航独立滚动，底部作者区可见；头像菜单保留快捷改密、个人中心、退出。双入口权限与 API 不因区域调整而改变：菜单只是呈现与入口授权，API 仍按契约权限点与 operation grant 服务端执行。

部门与数据范围（[ADR-0035](../adr/ADR-0035-action-permissions-departments.md)、[ADR-0036](../adr/ADR-0036-navigation-regions-granular-authorization.md)）：部门管理页维护自引用组织树（同父重名禁止，删除需无子部门且无用户挂靠）；用户创建/编辑弹窗选择所属部门（可清空），列表展示归属。用户域角色带数据范围 data_scope：仅本人（默认）、本部门、本部门及以下、自定义勾选部门集、全部（all 吞并一切，仍限于用户域数据，不包含管理员域或本地形态数据）。范围驱动用户域笔记/文件**列表、读取与签名下载**的一致过滤；范围内读取不开放对他人记录的修改/删除，写操作仍按属主或显式业务写规则执行。列表返回服务端计算的行级 capabilities，界面据此呈现真实可执行操作。多角色取并集，未知范围值按仅本人 fail-closed；范围解析或数据库错误直接拒绝请求，成员集合分批解析（单批上限 500），不静默截断、不降级。管理员域角色固定仅本人。

岗位（[ADR-0036](../adr/ADR-0036-navigation-regions-granular-authorization.md)）：岗位是独立目录（编码、名称、排序、启用、描述），普通用户可关联多个岗位，用户列表支持按岗位过滤，岗位展示成员数。岗位不隐式授予角色、菜单、动作、API 或数据范围，也不改变身份域；管理员账号不通过岗位取得用户域身份。停用岗位保留存量成员关系，新增关联只接受启用岗位；仍有用户关联的岗位不能删除。岗位 CRUD 要求 `posts:read`/`posts:write`，写入在安装锁事务内重查管理员并记录审计。

全局设置影响所有用户，但仅管理员可读写；公共 bootstrap/Logo/favicon/版权/最小登录策略不公开敏感数据。普通用户设置仅本地外观，不请求管理 API。服务端逐 API 校验有效管理员/权限，写入校验 CSRF/Origin；账号写事务重查管理员域操作者。用户域授权由 role_permissions 表驱动，未知权限点默认拒绝；最后启用管理员及最后有本地密码管理员不能禁用。

旧轨历史迁移 0007（旧自定义角色归普通用户）与 0008（管理员账号和企业绑定迁独立表，保留 ID/密码；两次升级均撤销旧凭据、取消待发邮件）是 Catalog 之前的编号，不是当前 [Catalog platform@7/@8](../03-runbooks/admin-tools.md)。升级前成套备份，恢复匹配 DB/目录/密钥和程序，见 [部署手册](../03-runbooks/deployment.md)。实现决策见 [ADR-0014](../adr/ADR-0014-separate-identities-management.md)，旧角色同表方案不作为当前规则。

当前双入口、单机边界和升级兼容说明见 [ADR-0016](../adr/ADR-0016-separate-client-admin-surfaces.md)。

个人中心完整需求与安全规则见 [运行说明](../03-runbooks/personal-center.md) 和 [ADR-0031](../adr/ADR-0031-personal-center-security.md)。包含昵称、两步邮箱验证、TOTP 与一次性恢复码、全部登录入口的二次验证、本人设备查看/单个或其他设备下线；不增加角色委派或普通用户管理权限。
