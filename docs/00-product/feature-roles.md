# 平台用户与角色权限

仅 web-platform 装配账号体系。全部账号存于 unicore_users，一个用户通过 unicore_user_roles 持有一到多个角色，业务成员、部门负责人、运营和系统管理是同一个账号的不同授权。用户和管理工作台保留独立页面与 API 入口，共用账号、Cookie、会话、个人资料、改密、找回、TOTP 与企业绑定；账号名、邮箱及手机号全局唯一。详见 [统一账号决策](../adr/ADR-0037-unified-user-identity.md)。

账号创建与编辑支持 role_ids 多角色集合；角色权限及 menu_ids/action_ids/operation_ids 分别取并集，菜单只影响入口，不授权 API。每个请求由后端按权限点、适用的 operation grant、超级管理员保留策略与 CSRF/Origin 校验。角色可同时持有业务和管理权限；realm 仅保留为工作台分类元数据。角色授权编辑器按用户端与管理端标明区域，同名菜单可分别授权。

超级管理员可直接为已有账号分配和撤销角色。仅有用户创建/编辑权限的运营人员可以创建默认成员、编辑状态和组织归属，不能借此变更角色或修改超管账号。公开注册与企业 JIT 固定 user，不接收客户端角色声明。super_admin 可以与其他角色并存，拥有全部权限；最后启用超管及最后有本地密码超管受事务保护。系统设置写入、角色管理、更新安装与存储配置等保留操作仍需超管。

部门树、岗位和数据范围适用于统一账号。岗位不隐式授权；角色数据范围支持仅本人、本部门、本部门及以下、自定义部门、全部账号，仅持有当前资源权限点的角色参与范围并集。用户列表/导出以及创建、修改均受对应范围约束；目标部门变更也需范围校验。全部范围可能包含持管理角色用户的数据，业务必须显式选择适用范围。

个人资源归属固定使用 user 身份，切换工作台不创建第二份文件、头像或笔记。管理文件操作仍需对应管理权限。个人中心与安全流程见 [个人中心](../03-runbooks/personal-center.md)。账号停用、改密及角色权限变化撤销共享会话，安全策略根据实际权限生效。

该未发布重构仅支持新安装，不提供旧双身份数据库迁移。新安装三方言均不创建独立管理员账号及其配套表。web-standalone、desktop 和 cli 的装配边界不变。

内置 user 是公开注册与企业 JIT 的默认角色，只允许业务权限与本人数据范围；管理权限通过额外自定义角色授予，不能把默认注册角色改成管理角色。

菜单直达、按钮与 API 的独立授权、角色更新保留语义见 [ADR-0038](../adr/ADR-0038-rbac-enforcement.md)。
