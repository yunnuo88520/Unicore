# 管理工具：日志、邮件、定时任务与表格

本页适用于 Platform 管理工作台，操作范围取决于当前账号的角色授权。菜单管理与角色权限位于“用户管理”；该目录还包含用户列表、部门、岗位、字典与任务。API 选择器内嵌角色编辑器的“高级”区域，没有独立目录页面。操作日志、邮件模板位于“系统管理 → 系统设置”下；用户管理提供适用的 XLSX 操作，文件元数据导出仅保留授权 API。普通用户、单机和桌面不提供这些管理 API。日志与邮件设计见 [ADR-0020](../adr/ADR-0020-audit-mail-templates.md)。

## 操作日志

按操作类型、操作者/ID、目标、详情或 IP 搜索；关键词中的 `%`、`_` 是字面字符。日期按当前浏览器本地时区解释，开始日包含，结束日包含整天（后端结束时间不包含）；清空筛选恢复全部。ID 与时间可切换正/倒序，时间相同以 ID 稳定排序；每页 20/50/100 条。ID、目标和详情截断时可悬停查看完整值。

导出沿用当前筛选和排序，忽略所在页，最多 10,000 条；到达上限会给出提示，请缩小范围。CSV 使用 UTF-8 BOM，时间为 UTC，单元格有公式注入保护。导出下载由已登录 SDK 完成，不生成公共下载地址。

新增操作记录快照当时的用户名与身份域。IP 是实际 socket 连接地址，Nginx 后可能显示代理地址；不会直接相信 X-Forwarded-For。旧记录没有的目标、姓名或 IP 显示空缺。日志不包含密钥、密码、验证码或邮件正文；通知投递标签提供最近 30 个队列任务、渠道类型及脱敏结果。

## 配置邮件模板

选择注册验证、登录验证码、密码重置、服务测试或系统通知；修改邮件主题和内容后保存当前场景。切换标签保留各自草稿；刷新前应保存。默认内容为中文业务内容，中英文界面切换不会改写内容，管理员可自行编辑为其他语言。

编辑器提供段落、加粗、斜体、有序/无序列表、撤销/重做、安全链接及源码模式。粘贴默认为纯文本。变量插入到当前主题或正文光标位置；源码模式也可插入。允许变量如下：

| 场景 | 变量 |
| --- | --- |
| 全部 | `{{site_name}}`、`{{site_url}}` |
| 注册、登录、重置 | 另有 `{{code}}`、`{{expires_minutes}}` |
| 系统通知 | 另有 `{{title}}`、`{{detail}}` |

账号模板必须在可见正文保留 `{{code}}`。预览和测试使用示例码 654321，不签发真实验证码。验证码正文的有效期仍由账号流程管理；模板不能更改验证码策略。主题最多 160 字符、禁止换行；正文最多 12,000 字符/24,000 UTF-8 字节。允许 p/br/strong/b/em/i/u/ul/ol/li/a/blockquote；仅 a 可有 href，值为 HTTP(S) 或 `{{site_url}}`。不支持图片、CSS、事件、脚本或任意模板逻辑。链接、变量和替换后的内容由服务端重新验证，不能靠前端净化替代。

「预览」展示当前草稿并保留品牌页眉、Logo 与版权页脚，在禁脚本的隔离 iframe 中查看。「测试发送」在弹窗填写收件邮箱，使用当前草稿直接等待 SMTP 确认；需先在邮件设置完成配置与真实连通性测试，每个管理员最多 5 次/分钟。测试成功代表 SMTP 接受，不保证收件箱投递。「恢复默认」须确认，仅恢复当前场景。

保存通过 `mail.template.{purpose}` 持久化，普通设置 PATCH 拒绝写入这些键；发送时自动读取，修改只影响后续新建邮件，已入队邮件使用当时快照。真实六位码、SMTP 测试和系统通知共用配置渲染；已 deprecated 的长链接兼容 API 仍使用原模板。

## 业务功能复用

邮件模板的“系统通知”外壳由内部 `Mail().Notify` 和自动事件邮件复用。通知模板页负责事件纯文本内容，系统通知页负责事件路由，通知渠道页负责企业微信 / Webhook 配置。配置、API 参数、Go 示例及任务状态见 [通知与邮件接入](../product/notifications.md)。直接邮件调用返回成功表示入队；SMTP / 企业微信 / Webhook 接受才会把队列任务标记为 sent，不代表用户已阅读。

操作日志的“通知投递”标签同时显示邮件、企业微信与 Webhook 的最近 30 个队列任务及脱敏结果，使用渠道列区分投递方式。

## 菜单管理

菜单管理默认显示「管理工作台」配置；切换「用户工作台」或「全部工作台」可以查看另一端，不会修改或删除配置。管理视图的「当前账号侧栏」状态按已保存配置与当前会话计算，不是其他角色的预览，也不包含未保存的修改。可从工具栏直接「添加页面」，再选择区域和适用的已注册页面；更改区域不会把用户页变成管理页。「我的笔记」和「笔记管理」的默认入口都在用户工作台业务区，管理工作台不呈现业务笔记页面。菜单行授权配置页面入口，业务动作、API 和数据范围继续在角色页管理。应用自定义控制台的页面导航由应用注册，不在共享菜单树里维护。

菜单管理维护真实导航区域：区域按 `surface` 区分用户端与管理端，区域下是 `目录、页面、链接、动作` 四类节点组成的树——目录用于组织，页面引用应用已登记路由，链接保存 http(s) 或站内 `/` 相对地址，动作是页面内授权节点、不作为导航入口；节点携带图标、排序、可见性、打开方式等字段。配置以 `navigation.{sections,nodes,version}` 整树保存，提交携带的 `version` 与服务端不一致时返回 409，需重新读取再保存；提交空数组按真正的空树持久化，不是“未修改”。“恢复默认”清空全部覆盖与外链、还原代码定义的默认区域与顺序，仅 super_admin 可执行；默认结构不存在字母序兜底，默认顺序调整必须随实现显式更新，操作员排序持久化在数据库。

配置对用户端与管理端侧栏同时生效，区域编辑器、完整侧栏、图标栏和移动抽屉消费同一导航模型：均按会话菜单授权逐页过滤，无权页面的父级整树隐藏；超级管理员的“菜单管理”入口强制可见，避免被自身配置锁死。服务端校验树深度上限 5、拒绝环；侧栏递归渲染整棵被授权子树：默认展开当前路径祖先、选中高亮，折叠状态本地保留；外链 http(s) 地址新标签打开（`rel="noopener noreferrer"`），站内 `/` 相对路径应用内跳转。可见性只是呈现，不撤销直达页或 API 权限；`menu_ids` 只过滤菜单可见性与入口，不授予 API 能力，页面、动作与 API 的授权在角色页分别勾选，互不隐含。扩展导航与页面见 [前端基础](frontend-foundations.md)。

新增或编辑页面时，先选择上级菜单和目标页面，再按需设置显示名称和图标。「选择图标」会打开可搜索的图标库；不选图标时沿用默认图标。排序、打开方式、角标和高亮设置在「排序与显示选项」中。

## 笔记管理

管理列表展示笔记标题、作者昵称（未填写时显示用户名）、状态和更新时间。和用户列表一样，输入标题或作者关键词即更新列表，状态下拉与关键词可组合，每次改变条件回到第一页。清空搜索框只清关键词，选「全部状态」清除状态条件。搜索框旁的「列设置」可显示或隐藏作者、状态、更新时间，偏好保存在当前浏览器，不影响筛选结果。有权限时点标题预览正文，或在行操作编辑标题和正文、修改状态、软删除。仅分配列表权限不会开放正文或写操作；编辑不会变更笔记归属、状态或原附件。软删除后作者也无法在个人列表查看，附件原文件保留。

## 岗位管理

岗位管理维护独立岗位目录：编码（小写字母/数字/`.`/`_`/`-`，64 字符内）、名称、排序、启用状态与描述。岗位展示成员数（`member_count`）；普通用户在用户创建/编辑弹窗可关联多个岗位（`post_ids`），用户列表支持按岗位过滤。岗位不隐式授予角色、菜单、动作、API 或数据范围，也不改变身份域；管理员账号不通过岗位取得用户域身份。停用岗位保留存量成员关系，新增关联只接受启用岗位；仍有用户关联的岗位删除被拒绝。列表要求 `posts:read`，新增/修改/删除要求 `posts:write`，写入在安装锁事务内重查管理员并记录审计。

## API 目录

角色编辑器高级 API 选择器与 `GET /admin/api-operations`（要求 `roles:read`，管理员域可授）从 `packages/contracts/openapi.json` 按 `operationId` 派生，展示方法、路径、摘要、标签、身份域与契约权限策略，用于角色 `operation_ids` 的授权勾选；不维护第二份手写目录，新增 API 登记契约后自动进入。认证、bootstrap、本人账号与恢复流程等必要 operation 及不可委派项不在可授予集合；operation grant 只能在契约允许范围内收窄调用面，不能替代权限点或保留集。

## 定时任务

任务页显示代码注册任务的名称、cron 计划、启用状态、最近执行时间/状态/错误、累计次数与下次执行时间。默认 `mail.queue` 使用 `@every 1s` 处理通知队列，`files.cleanup` 使用 `@every 1m` 处理文件清理，`announcements.refresh` 使用 `@every 1m` 检查公告发布时间/结束时间边界，仅在展示开启且跨越边界时通知用户刷新。关闭任务会暂停相应后台处理；启用状态保存在数据库，重启保留。

管理员可启停或手动触发已注册任务。触发响应只表示已接收，请通过任务列表或运行历史确认结果，不将请求成功当作任务完成。

自建任务可在页面创建、编辑与删除：任务名全局唯一（小写字母开头的 `a-z0-9._-`），执行计划支持 5/6 位（含秒）cron 与 `@daily`、`@hourly`、`@every 30m` 等描述符（保存时校验并归一化为秒位形式），执行器只能从代码注册的白名单中选择（当前为 `mail.queue`、`files.cleanup`、`announcements.refresh`、`logging.sweep`），业务模块可在组合根通过 `RegisterExecutor` 登记更多。不能上传脚本或执行任意命令。每个自建任务保留最近 50 条运行记录（开始时间/状态/耗时/错误码），内置任务不记历史；执行器被移除的任务行保持可见、可删，启动时被跳过并标记错误。实现使用 `robfig/cron/v3`，数据库用于启停、运行记录与自建任务定义，不承诺分布式调度或跨实例去重。查询与运行历史要求 `tasks:read`，创建/编辑/删除/启停/触发要求 `tasks:write`、管理员会话和 CSRF，并记录审计。

## XLSX 导入与导出

普通用户管理页可下载仅含标题行的导入模板、导入用户或导出用户，管理员账号页不提供批量导入。导入使用 `.xlsx` 首个工作表，首行为标题，后续按用户名、邮箱、初始密码、可选角色填写；角色缺省为 `user`。上传总量上限为 5 MiB，最多 1,000 条数据行、每行最多四列，ZIP 展开上限为 64 MiB；文件或结构超限时拒绝导入。每行复用用户创建规则及角色校验，结果返回成功数量和失败行号/原因。各行独立处理，失败不撤销已成功行；修正后仅重传失败行，避免重复创建。初始密码及导入工作簿属于敏感数据，使用后应妥善清理，不作为测试证据提交。

用户导出包含用户名、邮箱、状态、角色与创建时间，不导出密码或凭据。文件元数据导出 API包含文件 ID、名称、大小、状态、上传者及创建时间，仅导出元数据，不打包文件内容。XLSX 与日志 CSV 是独立入口；XLSX 从服务端按每批 50 条分页读取，最多导出 10,000 条，超限返回 `INVALID_INPUT`，不静默截断。导出沿用当前搜索条件，覆盖匹配记录的全部页；当前页码和隐藏列不改变导出范围。下载经登录 SDK 完成，无公共下载链接；用户导出要求 `users:read`，模板/导入要求 `users:create`，文件导出要求 `storage:read`，导入还要求 CSRF。

用户、管理员和文件列表提供“列设置”，选择仅保存到当前设备偏好，不修改服务端权限或导出字段；扩展方式见 [UI 组件参考](../product/ui-components.md)。

## 数据备份

升级或迁移前按 [备份指南](../product/backup.md) 保存数据库、私有目录、密钥和对象文件。任务定义、角色授权与模板保存在数据库中；恢复时使用匹配版本的程序与完整快照。

## 角色授权操作

新建角色先选择需要的页面，默认仅补齐祖先目录、路由点与可用浏览接口。展开页面后明确勾选创建/编辑/删除等按钮；按钮与 API 可分别撤销。共享页面的管理工作台按钮标明变体；角色分类不限制管理 API。纯 API 角色直接展开“高级”，按名称、方法、路径、模块或权限筛选完整 API 集合；选择 all 操作自动补齐权限点，any 操作先选择一个匹配点。保留点显示“仅超级管理员”。

也可在菜单行点击“分配角色”。先保存未提交的布局，再勾选角色并保存；新增页面补齐祖先与权限上界内的浏览接口，取消只撤销当前菜单。目录不批量授权子页面。其他角色属性、数据范围、按钮和 API 保留；只需受影响成员重新登录。若返回版本/角色集合冲突，关闭弹窗并刷新后重新分配。API/按钮需要彻底撤销时到角色页分别取消，不以隐藏导航代替服务端授权。

角色编辑保存携带读取时的 version，缺失拒绝、过期 409；冲突时显式重新读取并复核，不自动换版本重试。菜单节点补丁保留导航 version + expected_role_ids，实际改变角色时也递增角色版本。内置 user 数据范围固定 self 且只读，需放宽范围时先复制为自定义角色。菜单标签仅显式分配，不保证最终可达；super_admin 固定勾选、不可取消，其默认访问仍受 surface/区域/节点及祖先隐藏禁用约束。未分配、加载和失败分开显示，不用错误空态覆盖角色。

重置业务账号密码需显式 users:credentials:write 及其目标范围；改登录邮箱还须 users:update 及相应范围，trim/小写化后未变不触发新增凭据门槛。完整目标拥有管理访问能力时仅超管能改凭据；PAT 均不能执行管理端凭据写，包含本人和超管绑定令牌。新权限不自动授给已有角色，授权时同时检查适用 API/按钮与数据范围；本人安全流程仍按个人中心执行。详见 [ADR-0046](../adr/ADR-0046-credential-delegation-role-concurrency.md)。

已有角色若曾依赖旧版本的按钮自动补回，需要超管在编辑器明确勾选所需按钮。升级不推断空数组的意图，不自动恢复已撤销按钮；节点目录回填不等于角色授权。详见 [ADR-0040](../adr/ADR-0040-explicit-role-grants.md)。
