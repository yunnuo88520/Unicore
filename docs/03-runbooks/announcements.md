# 公告与站内信

Platform 管理员在“系统设置 → 平台公告”发布公告，普通用户从顶栏铃铛的“公告”标签查看。管理员只显示“通知”标签。Standalone 提供本地站内通知，不提供平台公告或外部通知渠道。

## 编辑与发布公告

新建公告默认为草稿、静默通知、全部用户可见。标题最多 200 字，正文最多 10,000 字，内部备注最多 100 字。正文支持受限 Markdown/HTML，预览与实际展示使用相同的安全渲染规则，不允许脚本、图片、嵌入页面、样式或事件处理代码。备注和接收人列表不会展示给用户。

发布状态包括草稿、已发布和已归档。填写未来发布时间即可定时发布；结束时间必须晚于发布时间，留空则持续有效。到期后停止展示，不自动改为归档。定时公告的客户端刷新可能延迟约一分钟。

接收范围可选全部用户，或搜索并选择最多 500 位指定普通用户。服务端按当前接收范围判断列表、详情和已读资格。

管理列表支持搜索标题、内容和备注，按状态筛选、分页和批量删除。多人编辑冲突时会提示重新读取；批量操作中任一条冲突则整批取消。

## 查看公告与阅读情况

铃铛“公告”标签显示当前可见的未读总数，列表每页十条，未读优先。打开详情会记录首次阅读时间；“全部标为已读”处理所有当前可见公告，包括其他分页。

静默公告只进入列表。弹窗公告会在进入工作台约三秒后逐条出现；点击“标为已读”并保存成功后关闭，失败时可重试。弹窗没有阅读倒计时，阅读记录表示打开或确认，不能证明阅读完成。

修改内容、通知方式或接收范围不会重置已读记录。需要再次提醒时请新建公告。管理员可在“阅读情况”搜索用户，查看当前接收资格和首次已读时间。

关闭公告展示后，用户端不再显示公告，未读数归零；重新开启后按当前有效期和受众显示。撤回、归档或移除接收资格也会让相应内容不可见。

## 使用站内信

铃铛的“通知”标签显示本人的站内信，支持展开、单条已读、全部已读和分页加载。站内信与公告分别保存已读状态，在一处标记不会自动改变另一处。

公告和业务模块可生成站内信。公告来源的消息仍受原公告的开关、状态、有效期和接收范围限制。当前没有独立的管理员任意发送站内信页面。

客户端在打开铃铛、窗口重新聚焦或接收服务端事件时刷新数据。网络断开期间，以重新连接后的查询结果为准。平台事件连接使用 SSE，反向代理应允许长连接，并关闭该路径的响应缓冲和缓存。

## 开发接入与备份

业务模块使用 `internal/notify` 门面登记类型并投递站内信；事务、幂等和操作按钮约定见 [通知事件参考](https://unicore.ebox.vip/03-runbooks/notifications#模块站内通知-登记式投递)。邮件、企业微信和 Webhook 使用独立投递队列，配置见 [通知与邮件](../product/notifications.md)。

公告、站内信和阅读记录保存在数据库。升级或迁移前按 [备份指南](../product/backup.md) 保存数据库、私有目录与密钥。
