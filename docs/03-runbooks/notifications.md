# 事件通知

仅 `web-platform` 提供。管理员进入 **系统设置 → 通知渠道 / 通知模板 / 系统通知**。普通用户不能读取配置、测试发送或修改开关；单机、桌面、CLI 不装配这些接口。平台公告的顶部铃铛仍独立管理公告，不是渠道消息收件箱。

## 从配置到启用

1. 在基础设置填写站点名称、站点地址和管理员邮箱。站点地址用于通知中的链接，管理员邮箱是管理邮件的唯一收件地址，不会向全部管理员群发。
2. 如需邮件，在邮件设置配置 SMTP，并完成真实投递测试。用户通知只发到事件所属普通用户的邮箱；管理员账户事件不会另发“普通用户通知”。同一事件中重复的邮件收件地址合并。
3. 在通知渠道选择企业微信群机器人或自定义 Webhook，填写凭据、开启渠道并保存，然后测试发送。两者只能选择一个，切换保留另一种已保存的配置。关闭渠道只暂停渠道投递，不关闭邮件。
4. 在通知模板选择场景，编辑纯文本标题、正文。变量按钮插入到当前聚焦字段的光标位置；预览与测试使用当前草稿和固定示例数据，不自动保存模板。HTML 与未知变量会被拒绝。
5. 在系统通知中分别配置普通用户邮件、管理员邮件、管理员渠道的事件开关，最后开启系统通知并保存。**系统通知默认关闭**，避免旧实例升级后意外发送；验证邮件、验证码登录与密码找回不受此总开关影响。
6. 在操作日志的投递记录中查看真实任务状态。渠道和邮件共用队列，记录仅显示任务编号、渠道类型、状态、尝试次数、时间和稳定错误码，不返回收件人、消息内容、回调地址或密钥。

邮件事件把通知标题/正文填入已有邮件模板的“系统通知”外壳，保留品牌页眉、页脚与 HTML 转义；通知渠道始终使用纯文本。事件邮件不在数据库事务中读取品牌图片文件。

缺少已测试 SMTP 或有效收件邮箱时跳过相应邮件；不会阻塞已配置的管理员渠道。IP 封禁无法可靠确定账户归属，只通知管理员。此事件的失败计数仍按进程和身份域隔离，重启清空。

## 渠道参数

| 参数 | 适用渠道 | 说明 |
| --- | --- | --- |
| 通知渠道总开关 | 全部 | 关闭后停止自动和测试渠道发送；邮件独立控制 |
| 机器人 Key | 企业微信 | 群机器人 Webhook URL 中的 `key` 参数 |
| 回调地址 | Webhook | 公网 HTTPS，允许带查询参数；禁止凭据、片段、私网、回环、链路本地地址与重定向 |
| 签名密钥 | Webhook | 可选，HMAC-SHA256 签名原始 UTF-8 JSON 请求体 |

三项凭据分别加密保存，GET 永不回显；空值保持不变，明确勾选清除才删除。启用渠道必须提供当前类型的必需凭据。不要把真实机器人 Key 或 URL token 放进仓库、截图或日志。

Webhook 使用 POST、`Content-Type: application/json`，字段如下：

```json
{"title":"Unicore · 账号登录通知","content":"账户：example_user\n…","event":"login"}
```

配置签名时，请求头 `X-Unicore-Signature` 是 `hex(HMAC-SHA256(secret, raw_request_body))`，不带前缀。接收方应在解析 JSON 前使用原始字节验证，并以恒定时间比较摘要。收到 HTTP 2xx 即视为成功；重试可能重复，接收方应按自己的业务规则去重。与 agu-auth 的 `X-Agu001-Signature` 采用相同签名算法，头名称按框架命名，不宣称协议字节级兼容。

企业微信发送 `msgtype=text`，`text.content` 为标题、空行、正文。既检查 HTTP 状态，也检查返回 JSON 的 `errcode=0`；响应体最多 64 KiB。请求超时 10 秒，不信任代理环境变量，不跟随重定向。DNS 解析结果须全部为公网地址，拨号使用已验证地址而 TLS 仍验证原域名，防止重绑定访问内网。

## 事件与模板变量

| 事件键 | 成功边界 |
| --- | --- |
| login | 密码、邮箱验证码、OIDC 登录完成；启用 TOTP 时在第二因素消费成功后 |
| ip_banned | 连续失败达到阈值，新产生一次临时 IP 封禁 |
| password_changed | 本人修改密码或邮件重置成功 |
| totp_enabled / totp_disabled | 验证器绑定 / 关闭事务提交 |
| account_disabled / account_enabled | 管理员修改账户状态，重复保存相同状态不通知 |
| registered | 无验证注册直接激活；需要验证时完成邮箱验证后 |
| user_created / admin_created | 后台创建对应身份，不包含安装引导账号 |
| sessions_revoked | 本人撤销设备会话 |
| email_changed | 完成换绑邮箱验证并更新邮箱 |
| alert_triggered / alert_recovered | 运行告警触发 / 真实恢复（见 [运行监控设计 §8](../00-product/design-runtime-monitor.md)）；默认仅管理员邮件，与其他事件一致受系统通知总开关统一控制；渠道投递仍需开启通知渠道并单独选择加入；通知设置页的用户对象不呈现这两个事件 |

账号停用对应框架已有 `disabled` 状态；不提供没有业务模型的“账号封禁/解封”、余额、订单和授权事件空开关。

所有当前场景可使用以下纯文本变量。用户输入只做一次替换，不递归展开为新变量，标题中的换行被清理。

| 变量 | 来源 |
| --- | --- |
| `{{site_name}}` | 事件入队时的站点名称 |
| `{{site_url}}` | 基础设置中的站点地址 |
| `{{username}}` | 事件目标账户，不一定是执行操作的管理员 |
| `{{event_time}}` | 事件发生的 UTC RFC3339 时间 |
| `{{ip}}` | 服务端连接上下文，不采信任意转发头 |
| `{{message}}` | 服务端事件详情，不包含密码、验证码或恢复码 |
| `{{rule_name}}` / `{{severity}}` / `{{metric}}` / `{{value}}` / `{{threshold}}` / `{{scope}}` / `{{instance}}` / `{{host}}` | 仅告警事件提供：规则名、级别、指标、当前值、阈值、资源视角、实例标识与主机名；其余事件渲染为空 |
| `{{occurred_at}}` / `{{duration}}` / `{{transition}}` | 仅告警事件提供：触发发生时刻（恢复通知携带原始触发时刻）、故障持续时长（触发通知为空）与阶段（`triggered`/`recovered`） |

## 后续业务接入

完整 SMTP / 企业微信配置、直接邮件 helper、事务内入队 helper 与 SDK 方法表见 [通知与邮件接入](../product/notifications.md)。

`internal/notifycontent` 管理事件目录、默认策略、受限模板验证与纯文本渲染。`mailer.Plan(values, mailer.Event{...})` 是纯函数，接收内部已解密设置快照，返回独立邮件 / 渠道消息；不读取数据库、不调用网络，也不向前端暴露任意发送 API。

现有身份适配器 `platformsql.eventNotifications` 在原身份事务中识别明确的成功事件，读取同一事务内的设置、目标账户，调用 Plan，将每条消息 JSON 用 `NotificationSecrets.Seal` 加密后写入既有 `unicore_mail_jobs`。业务、审计、队列原子提交；入队失败则业务回滚。不要在持有事务时调用另开数据库连接的 `Settings.Raw` 或 `Notify`，SQLite 单连接会死锁。不要把事件发送放在前端或用后台 goroutine 代替持久队列。

增加业务事件时：

1. 扩展 `notifycontent.Events`、默认模板和路由策略，明确收件对象、权限与事务边界，增加中英文事件文案。
2. 在业务持久化适配器的成功事务内调用 Plan 并持久化加密消息。传入目标账户最小快照；不传密码、令牌、原始请求或敏感审计详情。普通业务 usecase 依赖自定义事件 port，不导入 SQL 或 HTTP 适配器。
3. 添加真实事件入队、回滚、重复操作、两身份域与权限测试。涉及 DTO 时先改 OpenAPI 并生成；没有新增键或表时无需 schema 迁移。
4. 扩展页面与本手册。旧配置新增事件需要显式归一化/版本兼容策略，不能让现有模板配置因目录扩展而无法保存。

现有 `Mail().Notify` 仍是受信业务专用的直接邮件接口，沿用邮件模板中的“系统通知”；不会绕过或自动等同于此事件策略。要受本页策略控制的新功能应使用事件规划与事务入队方式。

## 运行、恢复和兼容

复用 `system_settings` 与 `mail_jobs`，无新表、无 schema 版本变更。`notifications.config` 登记为托管 SettingDefinition，保存事件规则和模板；三个 `notifications.*` 凭据登记为敏感项。普通 settings PATCH 禁止写这些键，专用接口原子校验保存并复核管理员身份。

进程每秒认领一个任务，60 秒租约，失败按 10/20/40/80 秒延迟，最多尝试 5 次；24 小时过期。关闭进程保留未完成租约，重启恢复，投递保证为至少一次。成功或终态清除载荷，终态元信息保留最多 7 天。发送使用入队时的内容和收件人快照，凭据在发送时读取当前设置。关闭系统 / 渠道总开关或切换渠道类型后，旧的相应任务被标记为 cancelled 并跳过，不继续发送；重新开启不会补发已跳过事件。事件内单独开关影响新任务，已入队内容不会被未保存草稿或后续模板修改替换。

备份需同时保留数据库及实例外置加密密钥，参考 [备份恢复](backup.md)。密钥丢失时不能解密凭据或未完成任务，应恢复完整备份，不要修改旧迁移 checksum 或把密文当明文导入。降级前关闭事件通知并排空队列；旧版本不理解渠道消息字段，不应直接处理新版未完成渠道任务。
