# ADR-0009：实例品牌使用规范化图片和持久引用

当前入口与单机范围以 [ADR-0016](ADR-0016-separate-client-admin-surfaces.md) 为准，以下保留原决策背景。

状态：接受 · 日期：2026-10-26 · 作者：yunnuo / ymz@ebox.vip

编译品牌由 identity.json/tokens.json 生成，但实例管理员还需要在运行时替换网站和邮件品牌。选择文件存储规范化 PNG、DB 保存内容哈希引用；不将 base64 塞入 MySQL TEXT，不修改生成静态资源，不允许原样 SVG 执行。

internal/branding 维护图片服务、尺寸/类型约束和存储 port；Web/桌面组合根注入现有 settings Store 与私有实例目录。三项托管设置登记在注册表，普通 PATCH 拒绝写入，避免绕过图片校验。没有 schema 变化，无需迁移；现有实例按默认空引用自然回退编译品牌。契约只新增 Branding DTO/operation 与可选 bootstrap.branding，旧客户端可忽略。

采用有限 JSON/base64 上传，便于 Web/Wails 使用相同输入；仅上传 operation 在 x-unicore.maxBodyBytes 声明 384 KiB，其他设置请求保持 64 KiB。服务限制解码前后体积和尺寸，重新编码最多 256 像素正方形 PNG；拒绝动态内容与客户端路径。图片公开但只能按当前引用的哈希读取；登录页需要公开品牌，持久配置和上传仍有独立权限。

顺序是原子文件 → DB 引用事务 → 清理未引用文件。DB 和文件系统不是同一事务，文件成功而 DB 失败可产生孤立文件，但不能先删当前图片。失败时仅在重新确认 DB 引用后清理，崩溃遗留在下次成功写入清理。进程实例锁阻止同目录多进程，服务 mutex 保护同进程读/写/清理。文件存储故障不会回显路径，读取缺失时 UI 回退默认；邮件读取失败返回服务错误，不能发送不完整快照。

邮件从规范化浅色图片派生最多 64 像素 PNG，预览与 MIME 使用相同副本。邮件载荷带该图片快照，图片后续清理不会破坏延迟发送；旧载荷兼容默认图。网站保留最多 256 像素，邮件以 42 像素显示。这将最坏图片字节控制在约 17 KiB，经 JSON/base64 和加密编码后仍须验证整个载荷低于 MySQL TEXT 的 65,535 字节。该取舍避免为小型内嵌标志引入大载荷迁移；队列终态清空载荷。

跨环境迁移必须成套迁移 DB、配置/密钥及 brand-assets。回退旧二进制会忽略托管键并显示旧编译品牌，不能删除数据库引用后期待图片自动恢复；正式回滚仍使用完整一致快照。原生包图标与运行时品牌各有入口，不通过上传重写已签名应用包。
