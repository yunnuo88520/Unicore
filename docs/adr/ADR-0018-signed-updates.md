# ADR-0018：可替换渠道的签名更新与离线历史

状态：接受 · 日期：2026-10-28 · 作者：yunnuo / ymz@ebox.vip

取代 ADR-0010 的升级占位；授权服务仍保持占位。影响 web-platform、web-standalone、desktop 与发行流程，CLI 不装配。应用数据库结构不变。

版本发现、可信发布清单、安装器分为独立 ports。默认公开 GitHub Releases，另提供 HTTPS JSON feed adapter，应用标识/渠道/信任公钥集中于 assets/updates，派生应用必须配置自己的仓库与签名公钥。在线平台只在管理员入口呈现，所有读取、检查、安装 API 独立校验管理员会话/权限，写入校验 CSRF/Origin；普通用户既无页面也无更新 API。单机与 GUI 没有平台身份，以本地实例边界使用共享页面。

每次构建内置由 CHANGELOG 生成的版本历史；远端历史成功后缓存到私有数据目录，断网/限流只标记检查失败，不清空本地或已缓存日志。远端文案作为纯文本，不执行 HTML。页面不因检查失败整体消失。检查与手动安装分开，没有默认自动重启或后台自动安装。

OTA 使用独立 Ed25519 发布签名，不将 SHA-256、GitHub 来源证明或 macOS 临时签名当作发行者授权。签名密钥仅存 GitHub 加密 Secret，公钥可提交；清单绑定应用标识、版本、目标 profile/OS/Arch、源码提交、大小/摘要、功能开关和迁移级别，并设有效期。检查及安装分别复核；拒绝降级、缺签名、错误应用/目标、篡改、过期及不兼容迁移。公钥轮换须先分发双公钥版本，再切换签名密钥，不通过远端 feed 注入新信任根。

Tar 与 GUI 在包目录外准备任务和复制更新 helper，下载与安全解包完成后才请求应用排空退出。helper 等待 instance.lock 释放，再在同一文件系统备份/切换程序目录；配置、实例密钥及数据库必须在安装目录之外。新程序以任务 nonce 和确切版本确认就绪，超时恢复旧程序。拒绝符号链接、路径穿越、设备文件、超限解包和不可写/不明确安装目录；中断任务保留可诊断状态和备份，不启动不可信程序。相同框架/业务迁移级别才允许原位自动安装；需要 DDL 的版本走停服备份和人工升级，程序回滚不冒充数据库回滚。

systemd 使用明确的 supervisor 重启模式、受限可写安装目录和更新 helper 生命周期配置；手动启动与桌面由 helper 拉起新程序。Docker 不挂 socket、不覆盖容器 binary，只显示当前/最新版本、日志和外部更新说明；未来可实现外部部署 adapter。

Apple Developer ID + hardened runtime、公证/staple、Windows Authenticode 为独立可选发布步骤，有配置才执行且失败阻断；请求正式系统签名但凭据缺失时拒绝构建。开发预览明确记录 unsigned，不能将接入脚本等同完成 Apple/Windows 的真实签名验收。

验收：签名/目标/降级/网络/解包攻击测试；管理员、普通用户与匿名允许/拒绝；离线日志与 PC/375px 浅深主题；隔离目录真实升级、失败恢复和配置持久化；原生 GUI 重启；三系统构建。未提供平台开发者凭据时仅验收流程和拒绝分支，不声称完成真实公证。
