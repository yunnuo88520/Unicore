# ADR-0028：服务器所有者明确解锁重装

状态：接受 · 日期：2026-11-02 · 作者：yunnuo / ymz@ebox.vip

安装完成后，匿名访问 /install 和持有旧凭据均不能再次创建管理员或初始化数据库。服务器所有者需要一个可审查的本地重装入口，因此接受私有 install.lock，不提供公开删除/解锁 API。本决策更新 ADR-0013 中“本站已完成标记也始终拒绝重新安装”的部分，其他实例仍拒绝接管。

完成安装先写入包含实例 ID 的 0600 install.lock，再保存 lock_version=1。旧版本 INSTALLED 配置没有这个版本字段时，按原配置验证、恢复 DB 后自动补锁；首次升级缺少文件不能解释成重装。非普通文件、损坏或错配锁拒绝启动。instance.lock 仍只负责进程互斥，不得混用。

仅在启动时发现已启用锁的 INSTALLED 实例缺少 install.lock，才解释为服务器所有者的明确解锁。管理员先停服并成套备份，再删除该文件并重启。运行中删文件不改变内存安装状态。配置、密钥和原数据不删除；原加密连接、实例 ID 和 profile 存为私有 reinstall intent，新实例 ID 和新 bootstrap.token 在安装前生成。旧 token（包括旧环境注入值）不能授权重装；重启未完成流程继续使用本轮文件凭据。

连接测试不清空/迁移。新空库可安装；本站原连接及实例/profile 标记匹配时允许重新确认清空；其他实例和归属不明的非空库拒绝，前端隐藏以外后端再次校验。前缀、站点名、域名不是所有权证明。确认清空必须勾选并精确输入库名，并在完成请求中再次检查。该操作删除整个专用库的表/视图与数据，不能用来保留旧账号/业务；保留数据走升级或匹配快照恢复。

reinstall intent 在失败后保留。没有 schema 所有权时不通过原 marker 自动宣布重装成功；MySQL 中途清空丢失 marker 后停止，另选空库或成套恢复备份，不能自动继续清空。DB 新标记/设置/管理员同事务提交；锁写入或配置收尾失败时按已提交 DB 恢复，不重复创建管理员。成功后新 token 吊销，原 intent 清除并重新锁定。文件目录不由安装程序删除。

适用 Web 两 profile；desktop 与 CLI 不新增安装向导。运行规则见 [安装规范](../00-product/feature-installation.md) 与 [部署](../03-runbooks/deployment.md)。
