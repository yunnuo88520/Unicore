# ADR-0029：框架表使用固定 unicore_ 前缀

状态：接受 · 日期：2026-11-02 · 作者：yunnuo / ymz@ebox.vip

框架结构需要与派生应用的业务表分开，并在产品改名和上游同步时保持可识别的稳定名称。因此当前框架所有物理表（含两张旧迁移账本与 Notes 样板）固定使用 unicore_，例如 unicore_users、unicore_system_settings、unicore_install_state。LicenHub 等派生项目保留它，product.name/slug、Go module 与部署卷不投影到表名。自建业务表自行命名，建议项目自己的前缀，不能占用框架保留名。表名前缀不代表实例所有权，安装仍验证持久配置与随机实例标记。

当前旧运行体系仍保留原 42 份 SQL 和原字节 checksum。三方言各追加 0013_prefix_core.sql（Web 单机/desktop）和 0013_prefix_platform.sql（Web 平台），只执行适用文件并记录其原字节 SHA-256。适用 profile 原本就不可在已安装状态切换，因此同一 version=13 的不同 profile 文件不会在同一实例交替执行。新安装先完成旧结构再统一重命名；旧实例先检查原归属，再执行保留行/外键的重命名，不重置 DB。

SQLite/PostgreSQL 的重命名与账本同事务；MySQL 使用单条多表 RENAME，DDL 不承诺与账本同事务。如果重命名成功而账本未写，重试必须验证完整旧名缺失/新名存在的预期集合后才登记；混合名称、目标冲突、checksum 不符停止，不 DROP、不覆盖。当前旧执行器原有中断 DDL 重试仍保留：已重命名库执行旧 SQL 时，只对可信历史 SQL 中固定框架标识符做名称映射，不修改字符串数据、源 SQL 字节或业务自建表。运行期业务查询直接使用固定新表名，不提供请求可控前缀。

本变更是当前旧体系的名称迁移，不启用 ADR-0024/0025 的 R1.0c namespace 执行器。尚未激活的九份 baseline 保留冻结原字节；未来接入前须追加各 namespace 的前缀尾迁移并调整账本定义，不能静默改写已发布 baseline/checksum。历史 baseline 验证 fixture 不代表本次运行结构，不能引用其旧结果宣称当前已验证。

升级前停服，使用匹配旧版本的工具成套备份；回退恢复升级前数据库/目录/密钥与旧程序，不能只换 binary。当前备份工具只恢复 schema=13 的同体系快照；旧快照使用对应旧工具。当前新工具拒绝备份缺少新账本的旧库，避免通过维护操作偷偷触发迁移。三方言、空库/已有数据/重复启动、双身份、文件/邮件/日志与备份恢复均需对应验证。
