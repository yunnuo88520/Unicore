# ADR-0032：Web 运维入口与 OS owner 恢复

状态：已接受。

## 决策

Web 发行包仍只有一个应用程序，直接运行/serve 为前台服务，manage/menu 为交互终端，start/stop/restart/logs 与 service 子命令操作 Linux systemd。业务 CLI 保持无平台/数据库依赖，不将运维命令注册为公开 HTTP API。

明确执行 service install 才创建 unit、有效启动配置、发现记录和可选命令链接；记录实际程序、工作目录与配置路径。默认通过 sudo 的原用户运行；直接 root 安装默认创建专用无登录账号，支持指定已有账号。没有隐式递归 chown、没有覆盖已有 unit/链接、没有在容器中安装 systemd。systemd 管理守护、自启和日志；用户模式的后台/开机运行受 login manager/linger 限制。卸载只移除受管服务及其配置/链接，保留数据和账号。

默认数据目录沿用工作目录下 data；受管服务的管理命令自动发现其启动配置与原工作目录，也可显式指定配置/目录。启动配置不增加明文数据库字段，数据库连接仍由 installation.json 加密保存。配置/状态输出排除 DSN、密钥、密码与令牌。环境文件按受限字面语法读取，绝不 source/执行 shell。

离线修复的信任主体是持有实例目录和原密钥的 OS owner，不是匿名网络访问者。实例不存在、未安装、缺失安装锁/原密钥或进程正在运行时拒绝，不创建新实例、不自动迁移、不复用安装 token。数据库修复在原库不可连接时仍可进行，但目标须为同类型、具有相同 instance/profile 的已迁好数据库；拒绝空库与其他实例，不实现跨引擎转换或搬迁。

管理员密码恢复不要求旧密码，写入标准 Argon2id 哈希，锁事务内撤销该账号会话和恢复挑战，审计 OS-owner 行为；不改用户名、角色、启停状态和已启用 TOTP/恢复码，不影响同名普通用户。没有清除 2FA 的恢复后门。会话撤销按固定身份域作用。

维护/后台路径使用既有 SettingDefinition 校验。site set-url 同时调整安装 origin 与邮件地址；文件和数据库不能跨介质原子提交，文件替换失败时尝试恢复邮件地址，主机在两次持久化间崩溃时由运维核对并重试。程序不配置 DNS、TLS、代理或企业回调白名单。

## 验证与支持边界

覆盖默认/覆盖/服务发现、缺失实例/密钥与运行锁拒绝、密码与身份域/TOTP 保持、同实例数据库连接验证和真实 Linux systemd 生命周期。原生 OS 的系统服务不冒充 systemd；Docker 由宿主编排管理，迁移与生产操作仍由部署者负责。命令参考见 [配置指南](../product/configuration.md#web-管理命令)。
