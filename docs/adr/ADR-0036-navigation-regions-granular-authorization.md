# ADR-0036：真实导航区域与细粒度授权

日期：2026-11-07。状态：已批准；三方言七组合基线验证已完成（见决策 10），其余构建与端到端验证结果以主线最终报告为准。本决策修订 [ADR-0034](ADR-0034-administrator-restricted-roles.md) 与 [ADR-0035](ADR-0035-action-permissions-departments.md)：取代「六个固定分组根」的菜单呈现模型，并把角色授权扩展为菜单/动作/operation 三类独立授予。

## 背景

ADR-0035 的菜单树仍把顶层节点钉在六个固定分组根上，分组不是可运营实体，配置编辑器与侧栏、图标栏、移动抽屉容易漂移成不同结构。把页面、按钮和 API 绑定到同一权限点，无法表达「能进页面但不能执行特定动作」或「同类业务仅开放部分接口」。部门范围若只影响列表，会出现可见文件无法读取、只读记录仍显示编辑操作；`all` 若不保留身份域条件，会跨域泄露管理员数据。`EnsurePermissions` 在每次启动幂等补种内置角色权限，会把管理员明确撤销的授权复活。

## 决策

1. **区域是真实实体，节点组成树**。迁移 `platform@7`（`migrations/platform/{sqlite,postgres,mysql}/0007_navigation_authorization.sql`）引入区域与节点持久化：区域按 `surface=user|administrator` 隔离，字段含 `id`、`surface`、`name`、`sort`、`visible`、`show_title`；节点类型为 `directory|page|link|action`，携带 `icon`、`sort`、`visible`、`open_mode`、`badges`、`active_menu` 等字段，`permission`/`operation_ids` 仅由 action 节点承载。目录用于组织，页面引用已注册路由，链接保存安全地址，动作是页面内授权节点、不作为导航入口。页面事实仍来自 `routes.ts` 编译期登记，菜单配置不生成任意可执行路由。服务端校验父节点存在、同区域同 surface、无环，树深度上限 5；区域可创建、修改、排序和删除。
2. **导航配置整树提交，版本号 CAS**。`GET/PUT /admin/menus` 交换 `navigation.{sections,nodes,version}` 结构；PUT 携带的 `version` 与服务端当前版本不一致时返回 409 版本冲突，需重新读取再提交。提交空数组表示真正的空树，按提交内容持久化，不视为「未修改」。`MenuSaveInput.reset` 请求恢复两域默认导航，仅 super_admin 可用；默认区域、节点与顺序由代码显式定义，不存在字母序兜底，默认顺序调整随实现显式更新。区域编辑器、完整侧栏、图标栏和移动抽屉消费同一导航模型，不在不同入口维护第二份结构。
3. **角色分别授予三类能力**。角色保存契约携带 `menu_ids`（菜单/页面入口）、`action_ids`（页面动作）与 `operation_ids`（可委派 API operation），提交空数组按输入错误拒绝。三者独立维护：`menu_ids` 只按角色过滤菜单可见性与入口，不授予任何 API 能力；勾选菜单或动作不自动授予 API，API grant 不自动显示菜单；父目录仅用于组织，不隐含整棵子树授权；直接进入已登记页面仍按页面授权校验。无权页面为 403，未知路由为 404。前端仅呈现真实存在的控件，不提供 KeepAlive、CloseTab 等无运行效果的假开关。
4. **API 目录派生自 OpenAPI**。管理端 API 目录页与 `GET /admin/api-operations`（要求 `roles:read`，管理员域可授）以契约唯一 `operationId` 为授权标识，展示方法、路径、摘要、标签、身份域与契约权限策略；不维护第二份手写 API 目录。认证、bootstrap、本人账号与恢复流程等必要 operation 及不可委派项不出现在可授予集合；新增 API 必须先登记契约并接入处理器与权限检查。
5. **运行时策略是授权上界**。每次请求同时满足 profile、access、固定身份域、有效会话、契约权限点、适用的 operation grant、`superAdmin` 保留集及 CSRF/Origin；operation grant 只能在契约允许的范围内收窄可调用集合，不能放宽权限点或保留集。`permissionMode=all` 要求全部权限点，`any` 要求至少一个，空权限列表不附加额外要求，未知模式拒绝。super_admin 保有契约内的管理能力与恢复入口，仍不能绕过身份域、CSRF、profile 或业务数据归属规则。事务内重查操作者与所需权限，防止鉴权后停用或撤权竞争。
6. **初始化不复活撤权**。权限目录同步与角色授权初始化分离：新增权限点登记、首次安装或显式兼容迁移可以建立初始授权；常规 `EnsurePermissions` 与进程重启只做幂等同步，不得重新授予已撤销的权限点、菜单、动作或 operation。角色定义或成员授权变更撤销对应域会话，并失效相关权限与组织范围缓存。
7. **岗位独立于角色与部门**。迁移 `platform@8`（`0008_posts.sql`）新增岗位表与用户多岗位关联：岗位有独立目录（编码、名称、排序、启用、描述），普通用户经 `post_ids` 关联多个岗位，用户列表支持按岗位过滤，岗位展示成员数 `member_count`。岗位不隐式授予角色、菜单、动作、API 或数据范围；管理员账号不通过岗位取得用户域身份。停用岗位保留存量成员关系，新增关联只接受启用岗位；仍有用户关联的岗位删除返回冲突。岗位 CRUD 走 `posts:read`/`posts:write` 权限点，写入在安装锁事务内重查管理员并记录审计。
8. **数据范围始终保留身份域**。用户域角色的 `all/dept_and_below/dept/custom/self`（默认 self）在用户域内合并，`all` 只覆盖用户域数据，不包含管理员域或本地形态数据。范围作用于用户域笔记与文件的列表、读取和签名下载；范围内读取不自动开放修改/删除，写操作仍要求属主或显式业务写规则及对应动作/operation 授权。列表返回服务端计算的行级 `capabilities`，界面据此呈现真实可执行操作。未知范围值按仅本人 fail-closed；范围解析或数据库错误直接拒绝请求，成员集合分批解析（单批上限 500）保证完整，不静默截断、不降级为仅本人或全部。管理员域角色固定仅本人。
9. **组织树安全与缓存一致**。部门新增、改上级与删除在事务内验证父部门、环与引用，变更后失效受影响的组织与数据范围缓存。部门不改变角色 realm；管理员域不参与数据范围。
10. **追加迁移并保留恢复依据**。`platform@7` 转换旧菜单配置并保留旧表/数据作为转换与恢复依据；`platform@8` 追加岗位。三方言各自追加迁移文件；已发布或已演练版本的历史 checksum 不修改，开发预览期内发现的结构缺陷在同一开发周期修正并重生成 checksum（@7 SQLite 两个单列主键补 NOT NULL，由 verify-baselines 结构比对发现），首个正式版发布后按 [迁移规范](../02-standards/database-migrations.md) 冻结。三方言七组合基线验证全绿：全库 54 表 = core@1 3 表 + platform 49 表 + module.notes@1 1 表 + 账本 1 表；生成列（如 MySQL `sibling_key` STORED）按校验器适配跳过显式赋值探针，不是基线缺陷。回退不做自动反向转换。恢复使用匹配的数据库、私有目录、密钥与程序快照；MySQL DDL 中断按迁移规范处理。

## 后果

- 导航结构、角色授权与运行时安全约束各有明确来源：页面登记在 `routes.ts`，菜单/动作配置在区域树，API 授权以契约 operationId 为准，运行时策略为不可逾越上界。
- 用户域可组合「可见不可用」「可用部分接口」「岗位相关但不授权」等颗粒；下游扩展页面时同步页面登记与菜单/动作节点，扩展 API 时同步 OpenAPI 与可委派目录，扩展资源时同步域过滤、读写规则与行 capabilities。
- 单机、桌面和 CLI 不装配平台区域 CRUD、角色三类授权、岗位或部门数据范围；共享界面仍只复用 WorkspaceLayout。
- 已知边界清理：ADR-0034 遗留的强制 2FA 域语义与文件服务 Admin 标志已按管理员域判定统一（见 [ADR-0035](ADR-0035-action-permissions-departments.md) 后果）。
- 本 ADR 记录批准的设计与已确认契约字段；实现与验证进度以主线报告为准，文档中的使用说明描述目标行为。
