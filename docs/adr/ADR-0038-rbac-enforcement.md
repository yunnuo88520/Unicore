# ADR-0038：独立授权与按权限点解析数据范围

状态：采用。补充 ADR-0037，取代 ADR-0036 中按权限点重新派生更新授权和跨工作台复用节点 ID 的规则。2026-11-09：节点 id 的工作台前缀方案被 [ADR-0039](ADR-0039-unified-grant-namespace.md) 取代为全局唯一 id；其余强制语义保持。仅面向未发布框架的新安装，不新增历史数据迁移。

## 决策

- 导航节点 ID 全局唯一。默认菜单使用 `user:路由`、`administrator:路由`；动作使用 `工作台:op:operationId`。自定义节点也必须全局唯一，route_id 保留页面标识。角色分类不限制跨工作台分配授权。
- OpenAPI `x-unicore.uiPage` 把可委派 API 注册为默认页面动作；`permissionMode=any` 的不同权限入口分别登记。按钮通过共享 `canAction` 校验权限点、当前工作台 API grant、有效动作和 action grant。页面通过有效菜单及祖先授权校验，直接输入 URL 也不能绕过。本人资料、安全及会话页面保持可达；超管保持恢复入口。
- 菜单、按钮、API 独立。菜单不授予 API，撤销按钮只撤销界面入口，直接调用 API 仍以 operation grant 为准；需要禁止调用时必须撤销 API。可复用动作不要求其登记页面的 menu grant，但隐藏、禁用的祖先会抑制动作。有效投影可携带无菜单授权的结构祖先，前端不可据其存在推导授权。
- 新建角色省略授权数组时，派生当前权限对应的初始授权；显式数组严格校验。修改角色省略菜单、动作、API、数据范围或自定义部门时保留原值，仅裁剪删除节点或收紧权限后失效的引用。增加权限点不恢复已撤销授权。角色编辑器提交明确数组，动作必须有相应权限点及 API。
- 数据范围接口必须显式传入资源权限点，只有授予该权限点的角色参与范围并集。文件角色的 all 不扩大笔记或用户管理范围。超管可访问全部；self、dept、dept_and_below、custom、all 的含义不变，数据库错误拒绝请求。
- 用户列表与导出统一采用 users:read 范围。修改先在事务内重查操作者、目标与 users:update 范围；创建按 users:create 范围校验目标部门；调整部门还需校验目的部门，非超管不能借修改本人部门切换管理范围。self 不能创建其他账号；部门管理者创建账号须指定范围内部门。角色分配仍仅超管可执行。
- 普通文件读取使用 files:access 范围，管理文件列表及导出使用 storage:read 范围，笔记附件访问独立使用 notes:access 范围。storage:read 不再自动赋予文件服务的全局管理员身份；仅超管在管理入口拥有该身份。文件删除仍按所有者及现有能力控制，业务示例不改变为部门写入。
- 部门/岗位目录、字典、任务、公告及实例配置属于全局对象，由各自 API 权限控制，不声称全部 API 都自动带部门过滤。新业务必须在列表、详情、导出和写入路径显式接入相应资源权限的数据范围；菜单和按钮不能替代服务端资源校验。

## 验证

覆盖省略字段保留、权限收紧、工作台 ID 冲突、页面直达、按钮独立授权、跨权限范围污染、用户列表与写入范围、文件读取和导出边界。笔记仅作为范围与动作接入示例；平台权限机制由共享组件和仓储校验提供。非平台形态保留原装配边界。
