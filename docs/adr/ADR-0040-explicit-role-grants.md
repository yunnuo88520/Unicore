# ADR-0040：显式角色授权与菜单反向分配

日期：2026-11-11。状态：接受。修订 ADR-0039 的页面默认联动、纯布局编辑器及按钮会话派生；统一账号与共享树仍按 ADR-0037/0039。

## 功能分类

仅 Platform（web-platform），访问主体为授权管理工作台中的超级管理员；普通菜单运营者只编辑布局。复用现有角色、菜单/动作/operation 关系表与审计，不新增 schema。呈现在角色编辑器和菜单行，Standalone（web-standalone/desktop）及 CLI 不装配、不呈现。后端策略、事务复核、CSRF 与数据范围继续独立执行。

## 问题

角色 realm 被前端误当授权边界，管理页面可见但缺 API；高级区只有权限点，无法给无页面 API 授予 operation。运行期从 API 补回按钮掩盖了显式撤销。独立只读接口目录不能完成授权，菜单页也缺少直接分配角色入口。

## 决策

1. 角色分类不限制授权工作台。页面按自身 surfaces 提供关联操作；默认联动路由点和已满足权限上界的 GET 操作，共享页面默认用户工作区。GET 不等于无写权限需求，导入模板等不得借此新增写权限。按钮明确勾选后补齐其点/API；共享页面管理变体分别标注。
2. 菜单、按钮与 API 独立撤销。取消菜单/按钮不删除独立 API，会话也不再根据 API 恢复按钮。高级区选择 all API 自动补所需点，any API 需要先选已有分支，不补其余点。撤销权限点同步裁剪失效依赖。
3. 完整 API 选择器内嵌角色编辑器高级区，包含无 uiPage 的可委派 API；保留目录接口，移除独立页面/菜单。保留权限元数据由服务端 super_admin 字段提供，不复制前端保留名单。内置 user 仍只允许业务点。
4. 菜单反向分配使用 `PUT /admin/menus/{id}/roles`，仅超管且同时要求 roles:write、menus:write。version 与 expected_role_ids 检查导航/当前菜单成员并发变更；安装锁事务读取最新角色后只合并所需变化，保留名称、范围和无关授权。新增页面补祖先和浏览接口，目录/链接仅当前节点；取消只撤销当前菜单。仅发生变化的角色成员会话失效。旧整树 role_assignments 留作兼容，新界面不用它。
5. 仅未初始化旧角色可在初始化边界一次性物化等价授权；已初始化空集合就是空。启动回填注册动作节点供编辑器选择，绝不把节点自动授给已初始化角色。已有显式 operation/action 所需 all 权限点的兼容派生保留；菜单和 any 操作不派生兄弟点。

## 兼容与恢复

不修改历史迁移、checksum 或真实实例数据。旧目录节点在既有启动规范化边界幂等移除，运营者的自定义子节点迁至最近保留祖先，清理对应旧菜单/动作关系，API 授权保留。旧目录地址按不存在处理。

以前仅凭 API 自动出现的按钮可能消失，这是恢复独立授权语义的必要变化；超管通过角色编辑器显式补选所需按钮，不根据空数组猜测旧意图。回滚采用实例备份与兼容构建，不以旧版本会话派生作为恢复方案。

## 验证要求

覆盖管理页面可读、默认不授写、无页面 API、any 分支无扩权、按钮撤销在刷新/初始化后保持、菜单反向分配的并发合并/冲突/超管保护及只撤销受影响会话；浏览器同时验证桌面和 375px。测试只使用隔离实例，数据库方言和原生载体未实测不声明支持。
