# ADR-0041：统一账号的客户端与 API 凭证

状态：部分被 [ADR-0044](ADR-0044-role-bound-personal-tokens.md) 取代（PAT 单角色模型、期限、管理入口与历史保留）；初始数据库已按 ADR-0042 收敛为 platform@1。客户端 JWT / Refresh Token 决策继续有效。延续 ADR-0037 的统一账号，以及 ADR-0040 的显式 operation 授权。

## 功能声明

- 功能领域 / 归属层：身份治理，产品功能。
- 定位：为移动客户端签发短期 JWT，为脚本签发可收窄的个人访问令牌。
- Platform：新增；普通用户与管理员复用同一账号、角色和资源归属。
- Standalone / CLI：不装配，无身份表、Token API 或令牌管理 UI。
- 访问主体：客户端登录沿用密码、验证码、人机验证、登录策略和 MFA；本人令牌管理仅 Cookie + CSRF；签名密钥轮换仅 super_admin + settings:write + Cookie。
- 持久化：追加 platform@10，三方言；凭证、Refresh Token 哈希/重放记录、加密的签名密钥。历史 SQL 不改动；MySQL 在追加版本统一旧个人安全表的关联键排序规则，保留数据。
- 契约：auth/token 登录、MFA、刷新、撤销；account/tokens 本人管理和 token-scopes；admin/auth/token-keys/rotate。
- 呈现：Platform 两工作台的个人安全页增加令牌卡片；无新菜单、无仪表盘组件。
- 依赖：安装密钥与平台数据库；不依赖外部 Redis/身份提供商。原有验证码及限流仍为进程内，多实例须保持现有部署约束。
- 关联：Cookie 浏览器会话、个人中心、RBAC、部门数据范围、审计与设备撤销。
- 待决策：无。本次不实现特定微信登录适配、OAuth2 授权服务器、多租户或服务账号管理界面。

## 决策

1. 浏览器继续使用 HttpOnly Cookie + CSRF。原生客户端显式传 Authorization: Bearer，不混合 Cookie；凭证错误不回落到其他认证方式。浏览器同源限制继续生效；不添加通配 CORS。
2. Access Token 使用 go-jose 的 HS256、固定 typ=at+jwt，严格验证 kid、iss、aud、sub、sid、jti、iat、nbf、exp；最长 15 分钟，不包含角色、权限或可直接充当 Cookie 的秘密。签名私钥加密存储；旧签名密钥仅保留 15 分钟验证窗口。HS256 签名秘密不向客户端或第三方服务分发，不提供 JWKS；JWT 是本实例 API 凭证，不承诺离线跨服务授权。
3. JWT 每次仍解析受控登录记录及现有会话，动态加载账号权限并执行原有策略。Refresh Token 只存哈希，每次刷新原子轮换；已消费 Token 再用则撤销整条登录链。SDK 对刷新进行 single-flight；网络丢失后的不确定刷新结果不能靠重用旧 Token 重试。
4. 客户端 Refresh Token 最长沿用登录会话的到期时间与安全策略（含空闲和管理员绝对期限），刷新不无限续命。登录设备页可撤销这条登录链。已配置 TOTP 时返回独立短期挑战（仅存哈希，内部待验证会话秘密加密保存），完成二次验证后才签发 Token，并原子替换原始会话秘密以消费挑战；强制 MFA 但尚未登记的用户须先在浏览器完成登记。
5. PAT 使用 ucp_ 前缀的高熵不透明秘密，仅创建时返回；只存哈希，最长 365 天，每用户最多 50 条有效 PAT。允许的 API 必须同时属于显式选择集合与账号当前的可委派 operation 集合；super_admin 的隐式放行不能绕过 PAT 的集合。认证、账号恢复、令牌签发与 superAdmin API 均不能由 PAT 调用。数据范围仍按当前角色及资源权限计算，不因 PAT 免除。
6. PAT 使用独立的会话撤销锚点，无浏览器设备明细，也不能当作 Cookie 使用。每次 JOIN 验证锚点存在，避免依赖 SQLite 的外键设置。账号禁用/密码/角色变化及“下线其他设备”等现有会话删除会同时使凭证失效；普通浏览器退出只撤销自身会话，不撤销独立 PAT。撤销后的记录保留用于本人列表和审计，不恢复秘密。
7. 统一主体由策略中间件传给业务适配器；模块不得再次假设所有主体都来自 Cookie。HTTP 之外的形态不引入本模块。外部登录适配器只能在完成身份验证和 MFA 后复用 Tokens.Exchange；不得相信客户端提交的 openid 或自行声明的角色。

## 后果与验证

这不是全局替换 Session，也不是开放任意浏览器跨域调用。Token API 响应不缓存；日志不记录原始凭证。用户需妥善保存一次性显示的 PAT，客户端应使用系统安全存储并串行刷新。服务账号和具体小程序身份适配可在这一主体与凭证边界上追加，不能复用员工密码代替独立机器身份。

验收覆盖 JWT 声明/密钥校验、无 Cookie API 调用、CSRF 保留、混合凭证拒绝、PAT 越权/所有权、刷新轮换/重放/并发、MFA/恢复码、密钥轮换、账号禁用/改密/角色/设备撤销与 Platform 形态隔离。
