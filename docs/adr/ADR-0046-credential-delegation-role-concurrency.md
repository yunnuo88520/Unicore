# ADR-0046：凭据委派、角色并发版本与共享迁移归属

日期：2026-11-15。状态：接受。补充 ADR-0037/0038/0040/0044；迁移成员归属保留现有 Catalog，并由维护者在本次明确确认，不将数据库表存在等同于身份治理装配。

## 功能分类

- 功能领域与归属：Platform 身份与访问治理，产品功能；为管理工作台运营者提供有界的业务账号凭据委派及无覆盖的角色编辑。
- Platform：普通业务目标的凭据操作可显式委派；完整目标账号具有管理访问能力时仅超级管理员可操作。角色写入和菜单角色分配仍仅超级管理员。
- Standalone：Web 与 desktop 均不装配账号、认证或角色治理，不增加页面、菜单、设置或权限提示；两载体仅按既有 Catalog 成员执行相同迁移。CLI 无 UI、身份或数据库，不适用。
- 持久化与契约：复用统一账号、安全状态及角色授权关系；新增三方言 `platform@4` 的 `unicore_roles.version` 列。密码重置使用独立权限点，邮箱更新增加条件鉴权；Role 返回 version，角色更新输入须携带 version，创建不需要。
- 呈现：用户管理按凭据资格呈现改密/邮箱编辑，角色编辑器处理版本冲突，菜单显示显式分配语义；无新增仪表盘组件或外部依赖。
- 待决策：本次无；未来数据库命名空间隔离须另行立项，不在本次调整 profile 成员。

## 背景

`users:update` 不能同时隐含任意登录凭据写入；只保护 super_admin 目标也会遗漏具管理能力的自定义角色账号。PAT 的单角色主体不得掩盖目标账号的其他管理角色。完整角色编辑与菜单反向分配等聚合写入共存时，仅导航版本不能阻止旧角色表单覆盖新授权。另有实际 Catalog 已含 `platform@2`，且三个 UI profile 均包含 platform，不能继续以「三个 namespace 各只有 version=1」「本地没有平台表」描述现状。

## 决策

1. **独立凭据委派**：新增 `users:credentials:write`，不自动授予已有角色，也不以 `users:update` 推导。可显式委派给自定义角色，用于范围内的普通业务目标。目标须从完整账号资源计算 `HasManagementAccess`（super_admin 或持有权限目录中非 Assignable 管理点），不能只看角色名、realm、当前工作台或 PAT 绑定角色；这类目标的密码和登录邮箱仅 super_admin 可改。事务持安装锁，重读操作者、完整目标与数据范围。
2. **按动作区分范围**：管理端重置密码要求新权限及其目标范围，不额外以 users:update 范围代替。登录邮箱是凭据；更新邮箱仍须满足原用户更新权限与目标/目的部门范围，实际变化时再同时满足新权限及其目标范围。输入邮箱先 trim 并小写化，规范化后与存值相同不触发新增凭据鉴权。仅改状态、昵称或组织不因提交未变邮箱而升级为凭据写入。
3. **PAT 禁止管理凭据写入**：包括本人、普通目标与超管绑定令牌，均不能通过管理端重置密码或实际改登录邮箱；不扩大为所有用户资料写入禁令。Cookie 操作仍遵守适用 operation、CSRF/Origin 与 MFA 门禁；本人 account 改密/换邮箱继续使用原有本人验证流程，不受管理委派替代。成功后按现有安全事务撤销会话与待用安全凭据，审计不得记录秘密。
4. **角色版本为聚合并发边界**：已有及新建角色从 version=1 起。`PUT /admin/roles/{id}` 必须携带读取到的正整数 version；缺失/非法拒绝输入，过期返回 409，成功原子递增。创建不要求 version。冲突后保留提示，由操作者显式重新读取并复核，不自动换成最新 version 重试覆盖。省略授权/范围字段保留与显式空数组撤销语义不变。
5. **所有聚合写入维护版本**：菜单节点补丁仍以导航 version + expected_role_ids 检查并发，并在锁内合并最新角色；实际改变角色授权时同时递增该角色 version。整树兼容 role_assignments、菜单规范化/裁剪、启动授权物化、部门删除带来的自定义范围变化等入口同样维护版本；没有角色实际变化的旁路写入不制造角色冲突，用户成员数变化不使角色编辑过期。导航版本不能替代角色版本。
6. **菜单分配不等于可达**：菜单行标签只表示显式 menu_ids 分配，不推算最终页面或 API 可达性。super_admin 在弹窗固定勾选且不可取消，不进入可编辑 role_ids/expected_role_ids；其默认菜单访问也不绕过 surface、隐藏/禁用节点、区域及祖先约束。角色未分配、加载中与加载失败必须区分，失败不能显示为空或允许以空集合覆盖。
7. **内置范围不放宽**：内置 user 数据范围固定 self，编辑器只读；复制成自定义角色后可调整范围。super_admin 的治理与保留操作语义不因该展示改变。
8. **保留共享 schema 现实**：沿用 Catalog：web-platform、web-standalone、desktop 均含 core、platform、module.notes（Notes 可按 edition 裁剪），CLI 为空。已有 platform@2 是收件箱 actions，新增 platform@4 只追加角色 version 列，不改写 @1/@2。Standalone 两载体同步迁移但不装配平台身份服务、管理 API 或后台。未来拆分 platform 表/命名空间属于独立兼容决策，不能借本次修复静默隔离或删除本地表。

## 兼容、迁移与恢复

旧角色不会自动得到新凭据权限；需要时由超管显式授予权限点及适用 operation/action，并复核数据范围。旧角色更新客户端必须先读取 Role.version，再提交更新；不能用缺失版本作为兼容覆盖入口。

`platform@4` 为追加列迁移，已有数据使用默认 version=1。仅向具有匹配 Catalog 账本、原 SQL checksum 与合法前缀的实例追加缺失尾部，不提供旧双身份或不匹配开发基线的原地转换。MySQL DDL 可先提交而账本未登记；不得把重试 ADD COLUMN、只看列存在或补造账本当作恢复。停止业务，使用匹配程序与升级前完整快照恢复到新目录/空专用库后再处理。

三个 UI profile 的 Catalog 指纹均改变，签名 OTA 不接受跨指纹自动安装。tar 停服备份后人工替换完整包，Docker 外部替换镜像且保留数据卷，不挂 socket、不在容器内覆盖程序；desktop 退出后按匹配快照和完整原生包处理，不用 HTTP 模拟桌面。回退须旧程序、数据库、配置、私有文件与密钥成套恢复，不能仅换旧 binary 或删除迁移账本。

## 验证要求

按入口覆盖普通目标委派、管理目标保护、PAT（含本人和超管绑定）拒绝、密码/邮箱独立范围、未变规范化邮箱和旧角色不自动授予。角色覆盖缺版本拒绝、过期 409、旁路写入使旧编辑过期、无变化不递增及显式重载。菜单覆盖 surface/隐藏/禁用祖先、固定超管行和加载/失败/空态，内置 user 范围只读及复制后可调。迁移覆盖三方言和三个 UI profile 的合法尾部升级、原数据保留、失败恢复与旧 Catalog 拒绝未来版本；空库检查不替代升级演练。验证结果只留任务会话或 build/、CI artifact，不在本文记录单次结果。
