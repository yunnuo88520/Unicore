# ADR-0051：平台文件治理与统一存储

状态：已接受。管理工作台提供正式文件治理功能，补充 ADR-0043；该 ADR 中移除测试文件页的决定继续适用于普通用户与 Standalone，不再限制平台超级管理员的治理页面。

## 决策

Platform 的文件管理是系统区一级页面，默认位于运行监控与 AI 管理之间。仅超级管理员可访问全实例文件目录、下载、删除和迁移；服务端契约与处理器独立强制这一边界。复用既有 storage:read/write，不把全局文件权限授予普通用户或业务角色。

治理目录以统一文件元数据为依据，包含业务附件、头像和规范化品牌资源。页面按存储位置与逻辑上传目录组织，提供分页、文件名/文件 ID 搜索和目录子树筛选；上传者显示账号姓名及用户名，系统资源与已删除账号使用明确标签。不扫描用户 Bucket，不暴露对象键、磁盘路径或凭据，不接管应用未登记的对象。

品牌上传与私有文件共用 files.Service 和 blob.Store；公开品牌只通过既有规范化资源端点访问。管理下载先鉴权再签短链接，不能由品牌公开例外扩大任意私有文件的可达面。保存品牌设置前回读并验证实际 PNG 字节，同名损坏对象允许重新上传修复。

批量迁移由页面先获取选中或当前筛选的就绪文件 ID，再串行调用既有迁移接口。全局只允许一个生效位置，新上传使用当前默认；历史位置仅用于读取与清理既有引用。迁移目标必须通过连接测试，且仅支持本地与云端双向转换，云位置之间直接互迁由服务端拒绝。批量选择按目标排除不支持的源和已在目标的文件；可显式选择全部成功后将目标设为全局默认，失败不切换。每个对象复制后核对大小与 SHA-256，再切换 location_id；file_id、用途和逻辑目录保持稳定，旧对象等待既有签名过期后清理。失败保留原引用，可重新选择失败项重试；页面显示逐项结果。这是当前页面内的操作，不承诺关闭浏览器后的后台任务。并发新上传不自动加入已经取得的批次。

删除先检查当前业务引用；品牌设置、头像或笔记仍引用的文件拒绝删除，到期清理也保留其元数据与对象。引用保护不延长既定下载有效期，解除引用后可按原到期时间清理。文件服务通过通用引用检查端口调用组合根注入的各业务检查器，不能直接依赖平台身份或笔记模块。新业务保存 file_id 时也须接入引用保护。

## 功能声明：platform-file-governance

- 领域与归属：平台存储治理，产品功能。
- 对象：实例登记的全部上传文件、存储位置和逻辑目录。
- Platform：超级管理员，storage:read/write 与 superAdmin 契约保留约束。
- Standalone：两个载体均不装配治理 API/页面，继续使用本地业务上传、下载和清理。
- CLI：不装配文件、界面或数据库。
- 持久化：复用 core 文件四表及既有位置；不新增表或设置。既有导航通过一次性种子补入新页面，保留运营者之后的删除和定制。
- 契约与 SDK：/admin/file-catalog 与 directories/access/delete；迁移复用 /admin/files/{id}/migrate；AppClient.fileCatalog 隔离业务 FileClient。
- 页面与组件：管理入口 /admin/files；共享 TreeView、DataTable 与抽屉，提供中英文及窄屏适配，无仪表盘组件。
- 环境：本地及已配置的对象存储，凭据与历史位置必须保持可用；未提供真实厂商账号时不声明云端验收。
- 待决策：无。
