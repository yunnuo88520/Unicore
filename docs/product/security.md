# 安全策略与加固

报告漏洞与当前安全检查范围见仓库根的 SECURITY 策略文件，GitHub 入口为私密漏洞报告页面。本页说明框架内置的安全机制与部署侧的最小加固清单；逐项操作步骤见 [从零部署](deployment.md) 与 [更新与签名](updates.md)。

## 报告漏洞

通过 GitHub 私密漏洞报告提交，或联系维护者 ymz@ebox.vip。**不要在公开 Issue 粘贴密钥、备份、安装凭据或用户数据**；提供受影响提交/profile、最小复现与影响范围。0.x 阶段只维护 main 的修复，不承诺历史版本安全支持或响应 SLA；修复在 CHANGELOG 标明影响与升级要求。

## 内置机制一览

| 机制 | 行为 |
| --- | --- |
| 会话与身份 | 管理员/普通用户独立身份表、独立会话 Cookie 与固定 API 路径；会话过期整批失效 |
| 请求防护 | 同源校验 + 非安全方法 CSRF 令牌；API 永不回落 HTML；安全响应头与 CSP 默认开启 |
| 权限执行 | 契约声明访问策略，运行时 fail-closed：未声明契约的已注册路由直接拒绝；权限点与 superAdmin 由服务端逐一校验 |
| 机密存储 | SMTP/OIDC 机密经密钥封装（`secret.key`）落库，接口响应不回显敏感值 |
| 安装边界 | 一次性 bootstrap token 完成安装后吊销删除；已安装实例拒绝重复初始化与非空库覆盖 |
| 更新信任 | Ed25519 发布者签名、SHA-256、平台匹配与防降级；签名与公钥状态以 Release 说明为准 |
| 审计 | 管理面变更写入审计日志（操作者、IP、目标），可在后台检索导出 |

## 部署加固清单

- 全程 HTTPS：安装前固定最终域名与证书；安装 origin 用于 Secure Cookie 与 OIDC 回调，装后不可通过后台设置迁移。
- 数据库最小权限：专用库 + 专用账号，端口只对应用网络开放；不要复用共享业务库或超级账号。
- 凭据卫生：bootstrap.token 用后即焚；`secret.key` 与备份同等级保护，丢失即无法解密历史机密。
- 最小公开面：应用 3000 端口只绑定本机/私网，公网只放行 443；监控端口（如启用）保持本机采集。
- 进程隔离：tar 部署用非 root 服务用户与 `ProtectSystem=strict`；Docker 部署镜像默认只读根、去能力、无 shell。
- 及时更新：订阅 Releases，按 [更新](updates.md) 停写、备份、切换、验证；回退用匹配旧程序 + 完整备份。
